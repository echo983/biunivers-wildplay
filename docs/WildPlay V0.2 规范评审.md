# WildPlay V0.2 规范评审

状态：通过，可施工

日期：2026-07-29

## 结论

方案必要、可行，且与现有 Resource Session 随机读取模型闭合。字幕作为旁路能力，不扩大
宿主协议，不影响已经稳定的音视频播放。

## 保留的必要能力

- 文本字幕轨发现和选择；
- Cue/Cluster 随机定位；
- Range 按需读取；
- Seek generation 隔离；
- UTF-8 和 ASS/SSA 可读文本；
- DOM 安全文本叠加；
- 字幕错误与主播放错误隔离。

这些能力分别解决“用户能选”“大文件不全量下载”“拖动后不串字幕”和“坏字幕不拖垮播放”，
不能再删。

## 删除或推迟的低必要性能力

- 图形字幕；
- 完整 ASS 排版引擎；
- 字体附件；
- 外挂字幕；
- 自动语言选择和偏好持久化；
- 字幕延迟、字号和样式设置；
- 无索引文件的后台全量扫描；
- 音轨选择；
- 通用 MP4/WebM 字幕。

其中音轨选择是独立能力，等字幕路径通过真实 MKV 验收后再设计，不与本次施工捆绑。

## 闭环检查

输入：现有 Resource Session 提供文件大小、可续租会话和精确单 Range。

定位：Matroska 的 SeekHead/Cues 提供 Tracks 与 Cluster 位置；无字幕 Cue 时允许以其他轨
Cue 定位 Cluster。

解析：Block 的 TrackNumber、相对时间和 BlockDuration 足以形成文本 cue。

消费：现有播放器持续上报 position，字幕控制器据此预取和选择当前 cue。

撤销：关闭字幕、切轨、Seek、切文件和页面卸载都会使旧 generation 失效。

失败：字幕不可用时保留音视频播放，并给出局部提示。

因此正常路径、Seek 路径、释放路径和失败路径均闭合。

## 剩余风险

现实 MKV 的索引和字幕封装差异较大。施工必须先用合成样本覆盖 EBML 边界，再用至少一个
真实 UTF-8/ASS 多字幕 MKV 验收。若样本没有任何 Cue，V0.2 明确报告“不支持随机访问”，
不以全文件下载掩盖问题。
